# webdav

단일 유저 nginx WebDAV. 내가 지정한 특정한 폴더를 통으로 서빙한다.

## 방식

`/폴더/`에만 autoindex HTML을 주고, 거기에 JS/CSS를 얹는다.
DAV verb (`PROPFIND`/`PUT`/`MKCOL`/`MOVE`/`COPY`/`DELETE`)와 XML 응답은 손대지 않는다.
브라우저에서만 UI가 보이고, WebDAV 클라이언트는 영향이 없다.

## 브라우저 기능 (표준 WebDAV 매핑, 전부 1차)

| 기능 | Method | 브라우저 UI |
|---|---|---|
| 목록 | `GET` (autoindex HTML 파싱) | O |
| 목록 | `PROPFIND` (Depth: 1) | O (이동 목적지 트리) |
| 이동/다운로드 | `GET` | O |
| 폴더 생성 | `MKCOL` | O |
| 파일 업로드 | `PUT` | O |
| 폴더 업로드 | `MKCOL` (재귀) + `PUT` | O |
| 삭제 | `DELETE` | O |
| 이름변경 | `MOVE` + `Destination` | O |
| 복사 | `COPY` + `Destination` | O |
| 다른 폴더로 이동 | `MOVE` + `Destination` | O |
| 폴더 다운로드 | njs 목록 + `mod_zip` 스트리밍 (`X-Archive-Files`, CRC `-`) | O |
| 업로드 진행률 | `PUT` (XHR) | O |

서버가 그대로 통과시키는 표준 명령: `OPTIONS`, `HEAD`, `PROPFIND`, `PROPPATCH`, `MKCOL`, `GET`, `PUT`, `DELETE`, `COPY`, `MOVE`, `LOCK`, `UNLOCK`.
브라우저 UI는 위 표의 것만 쓰고, 나머지는 WebDAV 클라이언트용으로 유지한다.
참고: `MKCOL`은 trailing slash 필수 (`/새폴더/` O, `/새폴더` → 409, nginx 동작 실측). `/폴더` 접근은 301로 `/폴더/` 정규화된다 (`port_in_redirect`/`absolute_redirect` off).

## 동작별 예외 정의 (스펙. 코드가 이 표를 따른다)

정책 4종: `확인`= 실행 전 묻는다 / `차단`= 서버 요청 없이 막는다 / `기록`= 상태 1줄만 남긴다 / `그대로`= 서버 동작을 둔다. 근거: RFC 4918 §9.3(MKCOL 405/409)·§9.6.1(DELETE=Depth:infinity 재귀)·§9.9(목적지 존재 시 MOVE가 삭제, Overwrite 적용) + nginx 1.28.3 실측.

| 동작 | 조건 | 정책 | UI |
|---|---|---|---|
| 공통 | 계정 틀림·변경·만료 (401) | 그대로 | 페이지 리로드 → 네이티브 로그인 창. 기록 없음 |
| 공통 | 로그인 5회 연속 실패 (성공 리셋) | 차단 | 1일간 444 무응답. 맞는 비번도 막힘. 해제는 restart. 기록 없음 |
| 공통 | NAT 공유IP 연대 차단 | 차단 | IP 기준이라 같은 IP 타인의 실패에 말림. restart 해제 |
| 공통 | 첫 접촉 401 (Authorization 없음) | — | 세지 않음. DAV 클라이언트 정상 동작 보장 |

### 파일앱 공통 예외 (문서 근거. RFC만으론 안 나오는 것들)

출처: MS "Naming Files, Paths, Namespaces"(예약 문자·예약 이름·MAX_PATH 260·끝 점/공백) / Apple TN1150(HFS+는 분해형 저장·대소문자 무시 비교) / RFC 4918 §9.10(LOCK)·§14(조건부). 우리 스택 실측 병기.

| 조건 | 우리 스택 | 정책 |
|---|---|---|
| Windows 예약 문자 `< > : " \ \| ? *` | 저장됨(201 실측). autoindex 이스케이프+`textContent`라 표시·동작 정상 | 그대로. Windows 교환 시 해당 파일 접근 불가 가능 |
| 제어 문자·개행 포함 이름 | 저장됨(201 실측). XML/HTML 이스케이프 처리됨 | 그대로 |
| Windows 예약 이름 (CON/PRN/AUX/NUL/COM1/LPT1, 확장자 포함해도 동일) | Linux라 저장 자체는 됨. Windows에서 접근 불가 | 그대로 |
| 이름 끝 점·공백 | 저장됨. Windows 셸에서 접근 불가 | 그대로 |
| 대소문자만 다른 동명 (`A.txt`/`a.txt`) | Linux는 별개. 우리 저장소(Docker+macOS)는 합쳐짐(PUT→204 실측, NFD와 동일) | 그대로 |
| 전체 경로 260자 초과 (Windows MAX_PATH) | 브라우저·Linux 허용. Windows 클라이언트 실패 가능 | 그대로 |
| macOS NFD 저장 (자모 분리형) | 실측: 우리 저장소(Docker Desktop+macOS)는 같은 파일로 합쳐짐(NFD PUT→204). Linux 저장소면 별개 파일 가능 | 그대로 |
| `.DS_Store`/`._*` (Finder가 WebDAV에 씀) | 목록에 그대로 보임. UI에서 삭제 가능 | 그대로 |
| 잠금 LOCK (실패 시 423) | UI는 LOCK을 절대 안 씀. 해당 없음 (nginx http_dav 잠금 미지원) | — |
| 동시 편집 선행조건 (If-Match → 412) | UI는 조건부 요청 안 함. 단일 유저 last-write-wins | 그대로 |
| 0바이트 파일 | 정상 저장·표시 | 그대로 |
| 대용량 파일 | `client_max_body_size 0` (무제한, nginx.conf). 폴더 압축은 워커 1개 점유 | 그대로 |
| 이름에 `%` 리터럴 | 저장·표시 정상(201 실측, 1회만 디코딩). 과거 이중 인코딩 잔재(`%2520`)는 이름 변경으로 정상화 가능 | 그대로 |
| 심볼릭 링크 | 대상을 따라감 (GET 200 실측, 대상 내용 그대로 노출) | 그대로. 공유 폴더 밖을 가리키면 바깥 내용 노출 |
| 점 이름 (`...` 등) | 저장됨(PUT 201 실측). 숨김 아님 | 그대로 |
| 경로 4096B·URI 8k 상한 | UI 도달 불가(240B×17층·8k 라인). 초과 시 서버 코드로 수렴 | 그대로 |
| `.`/`..` 단독 | OS 예약+nginx 정규화. 상위 탈출 불가 | 그대로 |
| 한글·공백·특수문자 | 저장됨. URL 인코딩으로 처리 | 그대로 |

## 다운로드 vs 열기

파일 클릭은 둘 다 `GET` 1개다. 다운 vs 열기는 브라우저가 `Content-Type` 보고 정한다. `inline`이 기본, `attachment`를 붙여야 강제 다운로드다. 우리는 `attachment`를 붙이지 않는다.

## mime type

브라우저가 열 수 있는 건 최대한 열리게 한다. nginx 기본 `mime.types`는 `text/plain`에 `txt`만 있어 코드 파일이 다운로드되므로, `nginx.conf`에 코드 확장자 1019개를 인라인으로 추가했다. 목록 출처: mime-db + linguist.

| 열림 | `png jpg gif svg webp mp3 mp4 webm pdf` + `txt md html css js json xml` + `c cpp go` 등 1019개 |
| 다운로드 | `zip 7z exe dmg iso bin` 등 바이너리 |

확장자 없는 파일(`Dockerfile`/`Makefile` 등)은 `types`로 못 잡으므로 파일명 기준 `map`으로 지정한다. 목록 147개(linguist filenames 도트파일 + 대표 파일명, 출처: https://github.com/github-linguist/linguist/blob/master/lib/linguist/languages.yml)도 `nginx.conf`에 인라인. 그래도 못 잡히면 UI에서 `octet-stream` + 1MB 이하 파일에 "텍스트로 보기" 버튼으로 `fetch` 후 표시한다.

## 브라우저 UI

`ui/` 3파일 (바닐라, 외부 요청 0). 디렉토리 `GET`에만 `add_after_body`로 얹고, 파일 다운로드는 건드리지 않는다. `/_ui/`는 ETag 재검증(no-cache). 1년 캐시는 ui.js 갱신 누락을 일으켜 폐기.

* `shell.html` — CSS/JS 주입점. `ui.css` — 목록/메뉴/패널/모달. `ui.js` — `ui.md` 구현체 (헤더·목록·우측 패널·기록·정보·업로드·이동 모달·`refresh()`).
* UI 규칙 (모바일 우선, `ui.md`): 상단은 타이틀+경로+로그아웃만. 추가 버튼 3개(새 폴더/파일 업로드/폴더 업로드)는 우측 패널 상단.
* 행: 아이콘 | 이름+메타 | ! + ⋯ 메뉴 (열기·정보·이름·복사·이동·삭제, 폴더만 +zip). 데스크톱·모바일 동일.
* 우측 패널: 기본=기록(개수 무제한, 최근 200개 localStorage 영속, 최신이 위. 업로드 진행률 포함, 다운로드는 시작만). !·⋯→정보로 패널이 정보 보기로 전환 (`PROPFIND allprop`+`HEAD` 실측 항목만: 이름/종류/경로/크기/MIME/ETag/수정일. 만든날은 nginx 미지원. 항목 아래 Content-Type 실측 미리 보기: html(sandbox)·이미지·영상/음성·pdf·텍스트(코드 하이라이트: 인라인 단일 파일, 확장자 매핑, 256KB 이하), 그 외 섹션 없음).
* 토스트 없음. 변경 op는 `refresh()`로 갱신 (401 경계만 리로드).
* 파일명은 `textContent`로만 그린다 (XSS 방지).

## 로그인·로그아웃·세션

### 기본 auth 방식

Basic Auth 하나다. 세션·쿠키·토큰이 없고, 매 요청 `Authorization` 헤더 1개로 끝난다. 서버가 아는 건 bcrypt(cost 10) `.htpasswd` 1줄뿐이다. 로그인 상태란 브라우저가 origin(`http://host:port`)과 realm(`WebDAV`) 묶음으로 캐시한 계정이다. 만료가 없어서 브라우저를 닫기 전까지 유지된다.

비밀은 이렇게 다룬다. `.env`는 chmod 600 + git 제외. 비번에 `$`가 들어가면 `$$`로 적는다 (compose가 치환해버린다). `.htpasswd`는 컨테이너 안에서만 644로 둔다. **LAN을 벗어나면 TLS가 필수다.** Basic은 매 요청 base64를 흘리므로 도청되면 그대로 끝이다.

폼+쿠키 세션은 쓰지 않는다. 세션 백엔드(sidecar)가 따로 필요하고, DAV 클라이언트가 쓰는 Basic Auth와 공존 설계까지 얹으면 단일 컨테이너 원칙이 깨진다.

### 브라우저 직접 접근 로그인

브라우저로 주소 치고 들어가면 바로 로그인되게 http 응답을 나눈다. 계정 없는 접근은 401 + `WWW-Authenticate` → 브라우저 네이티브 창이 뜬다. 로그인 페이지를 따로 만들지 않는다. 한 번 통과하면 브라우저가 캐시해서 이후 요청에 알아서 붙인다.

403에선 창이 안 뜬다. 401만 창을 띄운다. 그래서 403은 웹 접근을 막지 않게 상태 그대로 두되(속이지 않는다) 페이지 안에 돌아갈 길을 둔다. [로그인 / 계정 전환] 버튼은 더미 계정으로 캐시를 비우고 `/`로 보내 401 창을 다시 띄운다. DAV 클라이언트는 표준 상태 코드만 보므로 아무것도 안 깨진다.

로그아웃도 같은 트릭이다. Chrome·Firefox·Edge는 더미 계정(`logout:logout`)으로 `/`를 한 번 때려 캐시를 덮어쓴 뒤 401 창을 띄운다. **Safari는 URL 속 계정을 무시해서 통하지 않는다.** 그래서 Safari에선 버튼이 브라우저 종료 안내만 띄운다. 확실히 끝내는 방법은 전 브라우저 공통으로 브라우저 종료뿐이다. 서버에서 강제로 끊는 방법은 `.env` 비번을 바꾸고 `up -d` → htpasswd 재생성 → 전 캐시 무효, 이것 하나다.

브라우저 실측 메모:

* 취소했다고 창이 저절로 다시 뜨진 않는다. 페이지 옮길 때마다 뜨는 건 캐시된 계정이 자동 재송신되기 때문이다.
* 특정 탭에서 1회 로그인 실패하면 그 탭에서는 다시 로그인이 안 된다 (아직 명확한 이유는 모름).
* `localhost`·`127.0.0.1`·LAN IP는 origin이 달라서 캐시가 따로 논다.

| 증상 | 원인 | 처방 |
|---|---|---|
| 연결 안 됨·빈 응답 (401이 아님) | 가드 차단 (5연속 실패) | `docker compose restart` 후 정답 입력 |
| 맞는 계정인데 401 반복 | 해당 탭에서 1회 실패 후 고착 (이유 미상) | 새 탭에서 로그인 |
| 취소해도 계속 창이 뜸 | 이동마다 캐시 자동전송 (정상 동작) | 정답 1회 입력으로 캐시 교체, 안 되면 브라우저 종료 |
| 로그아웃이 안 된 것 같음 | 캐시 유지 (트릭 미동작 브라우저) | 브라우저 종료 |

### IP 기반 로그인 시도 제한

njs 공유 사전(`js_shared_dict_zone` slab, `ngx.shared` 접근)으로 서버 안에서 처리한다. 판단 기준은 IP다. worker가 함께 쓰는 메모리에만 기록하고 외부 데몬·파일·DB는 안 쓴다.

| zone | 용도 | TTL | 값 |
|---|---|---|---|
| `watch` | 틀린 횟수 | 없음 (성공·차단 때만 삭제) | number |
| `ban` | 차단 표시 | 1d | string |

### IP 상태와 요청 판단

IP는 3가지 상태 중 하나다.

* **안전**: 기록이 없다. 거의 모든 요청이 여기다. gate 비용은 slab 조회 한 번이다.
* **경계**: `watch`에 있다 (비번을 1~4회 틀림). 성공 응답이 한 번 오면 기록을 지우고 안전으로 내린다.
* **차단**: `ban`에 있다. 성공 없이 5연속으로 틀리면 올라간다. 1d 동안 유지되고, 맞는 비번도 막는다.

요청이 오면 순서대로 판단한다.

1. gate: `ban.has(ip)` → 있으면 인증 전에 444로 끊는다. 본문 없이 연결 종료다. 없으면 통과.
2. 401인데 `Authorization`이 틀렸으면 → `watch.incr(ip)` → 5번째면 `watch`를 지우고 `ban`에 올린다.
3. 401인데 `Authorization`이 없으면 (첫 접촉 핸드셰이크) → 세지 않는다. 401 그대로 돌려준다. 정상 DAV 클라이언트는 여기에 해당해서 절대 안 걸린다.
4. 인증에 성공한 응답이면 → `watch.delete(ip)` (경계 강등).

slab은 휘발성이라 재시작하면 기록이 날아가 전부 풀린다. 그래서 차단을 푸는 방법은 `docker compose restart`다. zone 선언이 빠지면 부팅 자가진단이 실패해서 서버가 안 뜬다. 보호 없이 도는 일을 원천 차단한다. 차단 증상은 401이 아니라 연결 안 됨·빈 응답이다. 구현은 `njs/guard.js`, 연결은 `nginx.conf` (`error_page 401` + gate + `js_header_filter`).

## 폴더 다운로드 인프라/빌드

`njs` 목록 생성 + `mod_zip` 스트리밍. `/_zip/download?path=/폴더` 1개로 받는다.

| 부품 | 역할 | 파일 |
|---|---|---|
| `Dockerfile` | nginx 1.28.3 + `mod_zip` + `njs` 0.8.10 + dav-ext 커스텀 빌드. 1.30.x에서 `mod_zip` segfault라 1.28 고정 | `Dockerfile` |
| `njs` | walk 후 temp 목록 작성 → `X-Accel-Redirect /_zipasm` (CRC `-`, 캡 없음, 10분 TTL 정리) | `njs/zip-list.js` |
| `mod_zip` | upstream 목록을 subrequest로 가져와 zip 스트리밍 (임시 zip 0) | 빌드 포함 |
| 내부 경로 | `/_zipasm`(proxy) → `/_ziplistfile`(목록) → `/_zipfile/`(원본, `^~`+`internal`) | `nginx.conf` |

흐름: `/_zip/download?path=X` → njs가 `/tmp/ziplist/`에 목록 1개 → 내부 proxy → `mod_zip` 조립. `njs` 직접 응답에 `X-Archive-Files`를 붙이면 워커 segfault라서 proxy를 태운다 (실측). `/_zipfile/`은 `^~` 필수 (extless regex가 `Dockerfile` 등을 낚아채서 404 냄, 실측).

```sh
cp .env.example .env  # 값 채우기, chmod 600 .env
docker compose up -d --build
docker compose logs -f
```

주의: 커스텀 빌드라 CVE 패치 때 `docker compose build --pull`로 따라가야 한다. `CRC -`라서 끊김 재개는 안 된다.
